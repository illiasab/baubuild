Problems

Four problems sit between the campus and the student.

Problem 01

The work never meets the student

Campus Ops needs a shuttle widget in 48 hours. The library form accepts past dates. Staff copy attendance by hand. That work stays outside class.

Problem 02

The wrong student can take it

A hard project or a class project has no gate. If Request always works, a score of 180 can claim work that asks for 300.

Problem 03

A push has no owner

Submitted code can sit with no named reviewer. Work that was sent back looks the same as a new push.

Problem 04

Finishing leaves no record

There is no score a department can trust. A short exam would be enough to become the person who approves everyone else.

Solutions

Each problem has a rule in the portal.

Solution 01

The work never meets the student.

One board of real projects

Campus Ops, the Library, the Registrar, Student Affairs, and classes post the work. A student finds it and joins it.

Solution 02

The wrong student can take it.

Joining is a rule

Open projects take you in at once. A professor or dev lead project is only a request. A low score or the wrong class changes nothing. Urgent does not waive the score.

Solution 03

A push has no owner.

A person still decides

The AI writes a summary. A dev lead, or the professor on a class project, approves or sends it back. Only sent-back work can be resubmitted.

Solution 04

Finishing leaves no record.

The record moves once

An approved bounty is added to earnings and to the score a single time. Three of four on the exam does not make a lead. That takes the meeting with Ylyas.

How it holds

The screen displays the decision. It does not make it.

One set of rules

Join, score gates, tasks, review, bounty, and the exam live in a single module. The same rules are what the tests run.

Answers stay server-side

The exam questions reach the browser. The answer key does not.

A gate cannot be talked past

A score of 180 cannot become a 300 because someone pressed Request. Filters combine. They do not override eligibility.
